# Golem YSM Link

让 Modular Golems 的人形傀儡使用 YSM 模型。新工程，模组 ID 为 `golemysm_link`，不依赖旧的两个联动项目。

模型读取、加密模型解码和模型授权仍由原版 YSM 负责。本模组在客户端创建不加入世界、不运行 AI 的女仆绘制代理，将傀儡的状态交给女仆的 YSM 渲染器。

## 版本与依赖

客户端与服务端都需要本模组和以下依赖。此版本按这些具体发布版构建，其他版本需要重新核验接口。

| 项目 | 版本 |
| --- | --- |
| Minecraft | 1.20.1 |
| Forge | 47.4.18，接受 47.4.18 至 48 之前 |
| Modular Golems | 2.7.4 |
| Touhou Little Maid | 1.4.2-forge+mc1.20.1 |
| Yes Steve Model | 2.6.5-forge+mc1.20.1 |
| L2 Library（傀儡模组依赖） | 2.5.3 |

请由用户自行安装交付 JAR，替换同功能的旧联动模组后测试。本次构建不会自动部署到 `mods`。发布包不包含上述依赖或任何 YSM 模型文件。

## 使用

1. 通过 YSM 正常加载模型，确保服务器拥有模型，且当前玩家拥有其使用权限。
2. 打开有权操作的人形傀儡的装备页面，点击右上方第三个衣服图标，悬停提示为“更改皮肤：YSM（右键点击重置）”。三个图标使用一致的间距。
3. 页面复用 YSM 玩家选模界面的模型卡、文件夹、搜索和翻页。点击模型卡应用到傀儡，左上方“切换材质”打开原生纹理卡页面；选择纹理后由服务器确认保存，不改变玩家自己的模型。
4. 玩家皮肤、女仆皮肤和 YSM 皮肤互斥：实际选择一种后清除另外两种，打开选模页面本身不改变当前选择。右键 YSM 衣服图标，或点击选模页的“恢复外观”，会清除 YSM 并返回默认傀儡外观，不恢复已取消的旧皮肤；当前使用其他种类皮肤时，重置未启用的 YSM 不影响它。选模页返回按钮回到装备页面。
5. 回收的傀儡在物品栏和手持时继续显示所选模型和材质，重新放出后保持原选择。
6. 模型声明了自定义弹射物时，傀儡射出的对应弹射物会交给 YSM 原生渲染。例如“精灵酒狐”的普通箭使用其自定义箭模型；未声明的弹射物类型仍按原版显示。
7. 安装 Jade 时，瞄准使用 YSM 的傀儡会显示“YSM：模型名称”，按 YSM 当前语言读取名称，模型尚未加载或未提供名称时使用模型 ID。Jade 是可选联动，未安装也可正常使用本模组。

操作需要在傀儡 8 格以内，权限沿用傀儡模组的 `canModify`。界面使用 YSM 原生的客户端模型目录和授权标记；保存时仍由服务器核验模型、材质、授权、距离和目标。若服务器没有模型或不允许使用，会在界面显示原因。

选择保存在傀儡的 Forge 持久数据 `golemysm_link` 中，包含 `model` 和 `texture`。写入后同步给跟踪此傀儡的玩家，新开始跟踪的玩家也会收到状态。无需为代理生成真正的女仆实体。

本次修复保持版本号 1.0.0。世界绘制与装备页预览的动画代理分开，预览使用一致的前后帧朝向，避免库存预览临时旋转傀儡时污染世界动画。物品显示实体从原傀儡回收数据读取选择，缓存按实体实例隔离，因此物品与世界实体即使 UUID 相同也不会共用动画状态。兼容已有选择，无需迁移存档。

女仆选模页会清理缩略图缓存实体残留的 YSM 标记，让每个格子显示各自的女仆模型。旧存档若同时保存 YSM 与原有皮肤，实体加载时保留此前实际显示的 YSM，清除被遮住的其他皮肤记录。

弹射物在服务器生成时保存发射者的模型信息，沿用 YSM 的能力数据、追踪同步和存档机制。已射出的弹射物保持发射时的选择，不随傀儡之后换肤而变化；真实发射者、伤害和弹道仍由原模组处理。弹射物材质使用模型自身的弹射物配置，遵循 YSM 的弹射物模型显示开关。

管理员（权限等级 2）还可使用：

```text
/golemysm set <傀儡选择器或UUID> "模型ID" "纹理键"
/golemysm clear <傀儡选择器或UUID>
/golemysm inspect <傀儡选择器或UUID>
```

例如清除最近的人形傀儡：

```text
/golemysm clear @e[type=modulargolems:humanoid_golem,sort=nearest,limit=1]
```

模型 ID 和纹理键区分大小写，可以包含中文和空格；使用服务器/YSM 实际标识，不要将纹理键改写为 PNG 路径。管理员命令仍校验模型、纹理与 YSM 授权，控制台无法代替玩家使用受限模型。

## 动作与限制

代理映射傀儡的位置、朝向、移动速度、挥击、左右手、装备、生命与受伤状态、物品使用和盾牌格挡。具体能看到哪些动作由模型内的动画配置决定。女仆工作任务、轮盘表演、载具以及其他模组特有战斗动作没有完整映射。

傀儡挥击期间，渲染代理暂停由被动格挡推导出的盾牌使用姿态，挥击结束后恢复；真实傀儡的格挡能力不变。已验证“圣女酒狐”持盾时的三种剑击状态。

对于“花嫁酒狐”这类根据 Better Combat 是否安装来选择攻击分支的模型，代理按自身支持的普通攻击路径播放模型动画。此适配只改变本模组傀儡代理的 `ysm.mod_version('bettercombat')` 查询结果，玩家、真实女仆以及其他模组查询仍交给 YSM 原函数处理。不修改模型文件，也不为傀儡模拟 Better Combat 的玩家连击数据；仅包含玩家专用攻击、没有普通攻击分支的模型仍需模型作者提供非玩家适配。

YSM 模型未加载、原生组件不可用或渲染出错时，世界绘制回退为傀儡本体。预览与服务端实际保存状态分离，等待模型加载不代表保存失败。若没有可用模型，检查服务器的 YSM 模型目录和授权；若版本不符，按依赖表核对实际 JAR 版本。

代码使用了 YSM 2.6.5 的部分混淆 API，版本升级需要更新适配层。支持范围为上述 Forge 版本组合，不支持 Fabric。尚未覆盖所有整合包和模型，具体兼容性仍需在实际游戏环境中验证。

## 构建

使用 JDK 17 编译字节码；Gradle 可由 JDK 17 或 21 运行。如果 JDK 17 不在默认发现位置，将 `JAVA17_HOME` 指向其安装目录。

将下列用户自行取得的发布 JAR 放在工程 `libs`，或通过 `-PdevModsDir=绝对目录` / `GOLEM_YSM_DEPS` 指定其他只读目录：

```text
modulargolems-2.7.4.jar
touhoulittlemaid-1.4.2-forge+mc1.20.1.jar
ysm-2.6.5-forge+mc1.20.1-release.jar
l2library-2.5.3.jar
jade-11.13.2.jar
```

```powershell
.\gradlew.bat clean build
```

发行文件为 `build/libs/golemysm-link-1.20.1-1.0.0.jar`。首次构建需要网络取得 ForgeGradle、Minecraft 映射。Jade 11.13.2 仅为编译依赖，游戏运行时可不安装。编译时会在 `build/compile-api` 提取傀儡与 L2 Library JAR 的内嵌 API，仅用于编译，不打包进发行文件。
